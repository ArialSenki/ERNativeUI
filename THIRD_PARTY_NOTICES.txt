Research influences and interoperability
-----------------------------------------

Solid Uncapper's native in-game menu was the inspiration for starting
ERNativeUI. During development, Solid Uncapper's observable runtime behavior
also helped identify Elden Ring menu interfaces and later validate coexistence
between both mods. ERNativeUI therefore includes explicit compatibility logic
for chaining the native functions hooked by Solid Uncapper:

https://www.nexusmods.com/eldenring/mods/6640

The public elden-ring-transmog and elden-x source repositories by Thomas J.
Clark were used as references while cross-checking the distinction between
Elden Ring's lower-level four-argument `MsgRepository::LookupEntry` function
and the higher-level five-argument native UI text resolver:

https://github.com/ThomasJClark/elden-ring-transmog
https://github.com/ThomasJClark/elden-x

Development tools
-----------------

JPEXS Free Flash Decompiler (FFDec) 26.2.1 was used to inspect Elden Ring's
Scaleform GFX/SWF structure while researching and validating ERNativeUI's
structural transformations. FFDec is a development tool; it is not linked
into or redistributed with ERNativeUI:

https://github.com/jindrapetrik/jpexs-decompiler

Mod Engine 2 is the loading and test environment used for ERNativeUI. It is
not included in ERNativeUI packages:

https://github.com/soulsmods/ModEngine2

Elden Ring UI interoperability
------------------------------

ERNativeUI's end-user packages do not redistribute Elden Ring GFX files.
The host performs narrowly validated, in-memory transformations on compatible
settings- and title-movie bytes supplied by the game or mod loader. The
repository keeps derived reference fixtures for structural regression tests
and developer research; they are not installed into runtime or SDK binary
packages.

ELDEN RING and its original game assets are the property of their respective
owners. Development tooling that reads GFX files is intended for files
extracted from a lawfully owned copy of ELDEN RING.
